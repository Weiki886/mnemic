# 请求限流（#23 拆分 1/3）

服务默认启用进程内令牌桶，先按 socket IP 限制请求，再校验 Bearer Token，通过鉴权后再消耗有效 Token 的预算。准入在 JSON 解析、DB 访问和业务模型调用之前；被拒绝的请求不会进入处理器。错误 Token 只消耗 IP 预算，不消耗有效 Token 的预算。

| 预算       | 初始容量 | 每秒补充 | 身份上限                       |
| ---------- | -------- | -------- | ------------------------------ |
| IP         | 120 次   | 2 次     | 4096 个                        |
| 有效 Token | 240 次   | 4 次     | 1 个（当前只有单一全局 Token） |

桶按实际经过的单调时间连续补充，最多补满初始容量，每次请求消耗 1 次。不对失败请求退款：404、400 和业务失败也消耗已经通过的准入预算；Token 桶拒绝时，已消耗的 IP 预算也不退。慢请求、SSE 流只在开始时计一次，不逐帧或在生成中途限流，不代表限制并发生成数量或停止计费。

IP 身份取 Fastify `request.ip`，保留 `trustProxy: false`；忽略 `X-Forwarded-For`、`X-Real-IP` 和 `Forwarded`。在现有 Caddy 部署中，后端看到的是代理的 socket IP，经过同一代理的用户**共用 IP 预算**。NAT 用户同样共用出口 IP 预算。这是当前单用户部署的保守边界，不宣称实现按公网客户端 IP 限流；若要区分代理后的用户，需要另行明确可信代理边界，不应直接信任客户端转发头。

有效 Token 当前只有一个，所以它跨 IP 共用一个预算；不把 Token 本文、哈希或任意错误 Authorization 值存入桶。多个实例各自维护预算，进程重启或新建 app 会重置；不是跨实例配额，不用它承诺防止模型 Key 超支。

只有精确 `GET/HEAD /health`（可带 query）与来自配置 CORS 源、请求方法受支持的预检免计数。健康检查前缀、其他方法、任意 OPTIONS、未知路由均不豁免。预检只是传输协商，实际业务请求仍需鉴权和限流。隔离测试的 `auth:false` 保留 IP 限流，没有有效身份的 Token 桶不计数。

## 超限响应

返回 `429 application/problem+json`，`code: RATE_LIMITED`、`title: Too Many Requests`，包含请求 ID；附 `Cache-Control: no-store` 和整数秒 `Retry-After`。文案固定，不包含令牌、请求体或桶身份。可信 Web 源可通过 CORS 读取这两个响应头（`retry-after`、`x-request-id`）；外部源不获放行。

`Retry-After` 向上取整且至少 1 秒，表示这一层预算恢复所需的等待建议；并发请求可能再次消耗预算，其他层也可能仍受限。身份表容量满时返回完整补满间隔作为保守等待建议。客户端应向用户展示超限，不在后台自动重发有副作用的请求。

IP 表最多保留上限数量的身份。新身份到达时最多检查 64 个最旧桶，仅回收已经闲置到足以完全补满的桶；不驱逐活动桶来授予新突发额度。表已满且无法安全回收时，新身份同样返回 429。没有定时器或后台清扫，也不为每次拒绝额外打告警日志；既有访问日志记录响应码。

## 库调用与验证

正式入口直接使用默认配置，没有 HTTP 或环境变量关闭入口。嵌入调用可在 `buildApp` 的 `rateLimit` 中提供完整 IP/Token 桶参数和 `maxIps`：

```ts
buildApp({
  authToken,
  rateLimit: {
    ip: { capacity: 120, refillPerSecond: 2 },
    token: { capacity: 240, refillPerSecond: 4 },
    maxIps: 4096,
  },
});
```

只读一次配置副本，之后修改调用方对象不影响服务。参数拒绝额外字段与类型强转：容量为 1–1000000 的整数，补充速率为 0.001–1000000 的有限数，IP 上限为 1–65536 的整数，显式 null/false 等非法对象拒绝构建。无需新迁移、依赖、环境变量或代理配置修改。

离线验证（不调用真实模型、不需 DB）：

```sh
DEEPSEEK_API_KEY= DASHSCOPE_API_KEY= pnpm --filter @mnemic/server exec vitest run test/token-bucket.test.ts test/request-rate-limit.test.ts
```

单元测试以手动时间验证分数补充、容量封顶、回收与时钟回退；HTTP 测试验证鉴权/解析/DB 顺序、伪造转发头、CORS、预算隔离、并发与无副作用拒绝；真实 TCP 测试以 3 次容量并发发起 12 个请求，精确得到 3 次成功、9 次 429。

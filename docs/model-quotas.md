# 模型调用日配额（#23 拆分 2/3）

正式服务默认最多预占 **1000 次/UTC 日**模型调用，启动配置 `MNEMIC_MODEL_DAILY_CALL_LIMIT` 可设为 1–1000000 的整数。空值、0、负数、指数形式等非法配置以固定文案拒绝启动，不回显配置值。没有 HTTP、请求体、客户端或关闭开关。

这是全服务共享的**调用次数保护**，不是 token、金额或账单上限。一条用户消息可能产生查询嵌入、聊天、提取、索引等多次调用；模型可收取任意数量的 token，不能据此推算最大费用。与 #106 的进程内 HTTP 限流独立：后台 worker 同样受到日配额约束。

## 计数与持久化

每次进入 SDK V2 的 `doGenerate`、`doStream`、`doEmbed` 前，在 `model_daily_quota` 按数据库 UTC 日期原子预占 1 次。三槽位、全部项目/Provider、JSON/SSE、查询/索引嵌入、legacy/durable 提取及显式诊断 probe 共享预算。SDK 自动重试、提取 schema 反馈重试、嵌入分批各自重新预占；并非按 HTTP 请求或文本条数计数。只解析模型配置的 GET doctor 不计数，工厂构造也不计数。

该表仅包含 `day` 和 `calls`，不存内容、凭据、Provider、项目或请求 ID；用量统计仍由 #36 独立记录。额度判断不依赖可能写入失败的遥测行，也不会把拒绝准入伪造成一次模型用量或正文捕获。预占成功后模型失败、中断或进程崩溃均不退款；取消在预占开始前已生效时不计数，取消发生在数据库等待中则可能占用一次但不调用模型。预占和上游模型请求不可能构成数据库原子事务，因此它是保守的尝试计数。

同一数据库的不同进程/连接共享计数，应用重启不重置；次日新建一行，不删除或改写昨日行。以每次准入语句捕获的数据库 UTC 日期决定归属，已准入且跨过午夜的长生成仍计入准入日。历史行不自动清理。迁移可重复执行且不重置计数。

降低启动上限不会清空已用次数，已用达到新上限就拒绝；提高上限只增加剩余额度。多实例须使用一致的启动上限，应用不能阻止操作者部署不一致的配置或直接修改数据库。修改 `.env`/部署环境后需自行重启服务生效，不应删除计数行绕过保护。

## 触顶与故障

- 新的模型调用触顶：固定 pino 告警 `model daily quota exhausted`，不记录模型参数、凭据或原始异常。JSON 聊天返回 `429 MODEL_QUOTA_EXCEEDED`，含 `Retry-After`（距离数据库 UTC 次日，向上取整且至少 1 秒）、`Cache-Control: no-store`、标准 problem+json。SDK 把最后一次配额拒绝包装在 RetryError 时，同样映射为 429。
- 配额数据库缺表、写入/校验失败：固定告警 `model daily quota unavailable`，fail-closed，不调用模型。JSON 聊天返回 `503 MODEL_QUOTA_UNAVAILABLE`、`Retry-After: 60`，不把原始数据库错误写到响应或日志。日志器失败也不会放行模型。
- 已在运行的调用不被强行中断。已经开始返回的 SSE 不能再改 HTTP 状态码，沿用 `GENERATION_FAILED` 终帧与 failed 消息状态，不伪造完整回答；用户 Evidence 可能已落库。JSON 拒绝也可能已保存用户消息，客户端不要自动重发。
- 查询嵌入被拒绝时沿用现有关键词降级，recall 仍可能返回成功和真实检索轨迹；这不表示有额度可调用聊天模型。随后聊天调用仍会独立受限。只读 API、关键词检索和健康检查仍可用。
- 显式诊断 probe 返回现有报告，各槽位分别为成功/失败；额度不足时报告失败，不把本地准入拒绝当作 Provider 成功。
- legacy 提取沿用 degraded，不落候选事实；durable EXTRACT/REEMBED 沿用任务失败/退避重试，事实事务与成功回执不会因拒绝而被伪造。**本轮没有按配额日重置任务重试次数的调度器**：持续触顶可能使任务耗尽既有重试预算进入死信，次日不会自动复活，需操作者按队列流程处理。不能把“日配额次日可用”理解为“所有失败任务次日自动补跑”。

## 库调用和范围

正式 `src/index.ts` 在数据库可用时始终注入默认或显式启动上限，覆盖由该服务创建的全部模型路径。复用库的 `buildApp` 可显式传 `modelDailyCallLimit`；未传时保留原有库兼容行为，不自动读取环境或启用配额。直接调用 `resolveModel` 的内部脚本/嵌入调用方须通过受信 `ResolveOptions.admitModelCall` 注入同一 `createModelQuota`，不宣称能限制绕过该服务的外部模型调用或独立验证脚本。`auth:false` 隔离测试不影响显式启用的配额。

测试使用真实 PG 的并发条件更新、第二连接/应用重建、昨日和当日行、DDL 非法计数、存储失败，以及真实 TCP 诊断链路；模型全部为离线 mock，未验证付费账单。部署按原有流程先执行迁移 0015，再启动新服务。回滚服务会撤掉日配额保护，additive 计数表可保留，不回滚业务事实或既有用量行。

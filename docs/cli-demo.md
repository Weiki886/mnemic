# CLI 对话演示（#19 拆分 2/2）

## 准备

按根 README 安装、迁移并启动服务。在 Web 记忆中心选择已有项目，复制其 UUID；CLI 不创建项目。
服务端需配置 chat / extraction / embedding 三槽位。以下对话会调用模型，可能计费；
事实会经服务端异步提取、Gate、消解和向量索引写入该项目，请使用专用演示项目。

```bash
pnpm build
pnpm cli doctor
# 可选：真实探测模型，会计费
pnpm cli doctor --probe
pnpm cli chat --project <项目UUID>
```

在交互终端运行，尖括号占位需替换。`--server http://127.0.0.1:3000` 可指定地址；
也可从 shell 读取 `MNEMIC_SERVER_URL`。CLI 不自动读取 `.env`，不保存模型 Key、不直连数据库。
需先在 shell 导出与服务端一致的 `MNEMIC_AUTH_TOKEN`，经 shared client 传为 Bearer；
doctor 的 `authentication: OK` 才表示当前 Token 通过鉴权，缺失或错误则返回 401。

## 告知 → 新会话召回 → 更新

1. 输入 `本项目数据库选用 PostgreSQL`，回车，等待回答。
2. 输入 `/new`：提交旧会话后创建新会话。提交仅表示已触发后台处理，不表示已完成索引。
3. 确认后台处理完成后，输入 `本项目数据库选的是什么？`。
   预期回答 PostgreSQL，下面显示引用的完整记忆 ID、版本 ID 和摘要。
4. 输入 `更新一下：本项目数据库改用 MySQL`，等待回答和后台处理。
5. 再 `/new` 并询问数据库，预期回答 MySQL；记下引用的记忆 ID。
6. 生成中按 ESC / Ctrl+C 请求中断，看到“已中断 · 已保存”后继续输入，保留上下文。
   空闲时 `/exit` 或 Ctrl+C 提交并退出；其他命令处理中 Ctrl+C 等待命令完成再提交。

当前没有写回完成查询端点；不要把固定等待秒数当作索引完成保证。
可从 Web 记忆中心确认当前值，或退出后运行下述只读命令；尚未召回时先确认后台写回状态，
不要反复发送同一事实，以免制造额外佐证。属性抽取可能存在用词漂移，演示结果依赖模型输出。

```bash
pnpm cli memory <记忆ID> --project <项目UUID>
# 机器读取：直接执行产物，避免 pnpm 自身脚本日志
node apps/cli/dist/index.js memory <记忆ID> --project <项目UUID> --json
```

预期显示当前值 MySQL，以及历史版本的来源会话、消息和 Observation ID。该命令只读，
不提供人工修正或删除。请求详情时同时提供项目和记忆 UUID，大小写均接受。

`--json` 为机器读取保留原始数据，不过滤其中的终端控制字符或双向文本控制符；
请交给 JSON 解析器处理，不要将不可信 JSON 原样打印到终端。人工查看使用不带 `--json` 的命令。

## 拒答与错误

用另一个无记忆项目启动 chat，询问未记录的信息；预期明确显示 `不记得`。
该标志来自服务端 `abstained`，不依赖模型恰好使用哪几个字。

消息或提交超时后 CLI 不自动重试：服务端可能已经持久化请求。
先核对 Web 对话和记忆状态；不要把通信错误当成“没有写入”。关闭进程不会撤销已提交的消息。

## 查看服务端会话（#31 拆分 1/2）

无需交互终端或模型配置，即可按项目查看同一服务端上的历史会话：

```bash
pnpm cli sessions --project <项目UUID>
pnpm cli sessions --project <项目UUID> --limit 20 --offset 20
# 脚本读取：直接执行构建产物，避免 pnpm 自身日志影响 JSON
node apps/cli/dist/index.js sessions --project <项目UUID> --json
```

沿用 `--server`、`MNEMIC_SERVER_URL` 和 `MNEMIC_AUTH_TOKEN`；项目 UUID 必填，大小写均接受。
只发送一次项目范围内的 GET，不创建/提交会话，不读取消息正文、不调用模型，也不保存本地会话文件。
不同客户端请求同一服务端、同一项目即可看到相同记录（拉取式，不是实时推送）。

文本显示完整会话 ID、项目 UUID、标题、开始/结束时间、消息数和进行中/已提交状态。
时间保留服务端 ISO 格式，不按本地时区转换；终端展示过滤控制字符。
`--json` 成功时输出 `{ "project_id": "…", "limit": 50, "offset": 0, "sessions": [...] }`，
会话字段为 `id/title/started_at/ended_at/message_count`；原始字段内容保留供 JSON 解析器使用，不应直接打印不可信 JSON。

列表沿用服务端开始时间升序。`--limit` 默认 50、范围 1–1000；`--offset` 默认 0，须为非负安全整数。
两者只接受十进制整数字符串，不接受空值、小数或科学计数法；翻页通过调整 offset，不会自动拉取全项目。
本页为空会明确提示；空页不证明项目存在或整个项目没有会话。
成功退出 0，读取/鉴权/响应不兼容退出 1，参数错误退出 2；不回显原始上游错误，也不自动重试。

“已提交”表示现有 `ended_at` 非空，旧 ID 不能直接再发消息；使用下述 `resume` 创建续聊会话。

## 本地命令帮助与补全（#32）

对话中输入 `/help` 查看当前已实现命令。`/he` + Tab 补全为 `/help `，回车才执行；
`/` + Tab 只展示候选。未知命令、`/new extra` 等非法参数只报错，不误发给模型。
已有 `/new`、`/resume UUID`、`/exit` 保持原有会话语义；Ctrl+C 在生成中改为请求取消而非退出。
对话中可直接管理项目记忆（#32 前两轮）：

```text
/memory --type decision --limit 10 database
/forget 记忆UUID
/memory --status deleted
```

列表搜索 subject/attribute，默认只读 active 记忆；删除复用 Web 的软删除 API，不产生聊天 Evidence。
可在 Web 恢复后再次 `/memory` 查看。类型来自当前版本来源 Observation，未记录类型不参与筛选。
手动召回（#32 拆分 3/4）可用 `/recall PostgreSQL storage`，显示 trace ID、两路得分、融合分和入选/落选原因。
这会显式调用 embedding，**可能计费**；无可用 embedding 时沿用关键词降级，不生成聊天回答。
查询原文会进入检索轨迹表，勿查询原始凭据。检索不写聊天 Evidence，不改变 salience。
`/status` 展示当前会话/项目、精确记忆计数及生效槽位；`/config` 查看全局安全配置。
`/config set ProviderUUID chat new-model` 修改已有 Provider 的 chat 模型，`/config set ProviderUUID name New Name` 修改名称。
修改作用于全局后续模型解析，不调用模型、不输入密钥；embedding 端点/协议和模型切换需 REEMBED，不在轻量编辑器内修改。
用法、分页、计费和失败边界见 [斜杠命令](slash-commands.md)。

## 恢复与切换会话（#31）

```bash
pnpm cli sessions --project <项目UUID>
pnpm cli resume <来源会话UUID> --project <项目UUID>
```

需要交互终端。来源可以是已提交会话，也可以是上次进程异常退出留下的开放会话。
恢复会创建新 ID，引用服务器已有的完整历史；旧会话归档只读，不复制或重复提取旧消息。
终端显示净化后的历史原文与记忆引用。输入下一条消息时，服务端会把这些历史及新问题交给模型。

对话中输入 `/resume <来源会话UUID>` 可以切换：当前会话和来源在同一事务内归档，
然后开始新的续聊会话。`/new` 则不继承历史；空闲时 `/exit`/Ctrl+C 提交当前会话。
不存在/跨项目恢复失败时，不会提前归档当前会话。专用修正会话不能恢复。

归档开放会话可能触发尚未处理用户消息的异步提取，**可能计费**；新发送的消息也会调用模型。
恢复/切换响应丢失时不要盲目重试，应先用 sessions/Web 核对是否已经创建新会话。
其他客户端未完成的生成不属于快照；归档后迟到回答不会再追加到旧会话，原请求返回 409，
已保存的用户消息保留，模型调用可能已经发生。取消能力仍归 #33。

历史不是当前事实：模型优先使用当前检索记忆；已删除信念不会被额外重新注入，
但 CLI/Web 只读历史中的记忆引用仍可能显示已删除/失效信念当时的版本值，原始对话文字也仍保留。
软删除不等于清除历史或硬删除传播（#11）。有历史但未召回跨会话记忆时，CLI 会明确显示两者的区别。
长历史不自动截断或摘要，可能超过提供商上限。完整决定和边界见 [会话续聊决策](session-resume.md)。

## 边界与验证

- CLI 通过项目范围内 SSE 接口实时显示回答；ESC / Ctrl+C 请求服务端取消，等待保存后的 finish。
  中断不撤销已发生的模型费用。`resume` 恢复已持久化会话历史，不恢复中断的网络请求。
  协议和边界见 [流式输出](chat-streaming.md)。
- 提取为进程内后台任务（持久队列归 #21）；新会话立即查询可能尚未看到刚告知的事实。
- CLI 只调用 shared HTTP client，不读写项目文件，不执行命令，不编辑记忆。
- chat 需要 TTY；生成期间仅接受中断键，避免重复发送。收流预算 600 秒，取消确认最多 10 秒；
  普通会话管理请求 120 秒，详情与 doctor 25 秒。断流保留前缀，无有效保存确认时显示“保存未确认”，
  不自动重发、提交或续写；显式 `/resume 当前会话UUID` 核对服务端历史后继续（生成尚未结束会返回 409）。
- 本次开发验证：共享客户端单测、真实 Ink 输入组件测试；原生 PostgreSQL 上用测试模型替身
  完成上述召回、更新、出处和拒答流程，并通过编译后的 memory 命令和实际 PTY 的 Enter、
  `/new`、Ctrl+C。#33 新增真实 PTY 的 ESC、生成中 Ctrl+C、续写与空闲提交测试，
  用隔离项目写入测试库并核对两条 interrupted 片段和下一轮模型上下文；未调用真实计费模型。
  这些离线替身测试不替代真实模型质量评测。

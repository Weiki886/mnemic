# ADR-003：一表一主的模块所有权

状态：已接受（2026-09-17，Issue #42 §4）

## 上下文

monorepo 单服务内，多模块直连同一张表会使"谁在写这张表"无法回答，责任链（profile_dirty、audit_log 等）在审查中反复断裂。

## 决策

每张表有且仅有一个运行时 owner 模块；其他模块读写必须经 owner 暴露的 service 接口。表迁移的创建归属以各实现 Issue 为准（可与运行时 owner 不同）。模块、表与 owner 的映射固定于 #42 §4。

## 理由与取舍

以模块边界换可审计性：每条责任链都有确定答案。代价是跨模块操作多一层接口调用——单进程内成本可忽略。

## 后果

- 依赖方向规则：http → modules → infra，不可逆（#42 §4/§6）。
- 新增表必须先在 #42 §4 登记 owner，再写迁移。

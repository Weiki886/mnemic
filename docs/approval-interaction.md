# 审批交互与授权存储（#34，拆分 2/3）

本增量沿用 [审批策略基座](approval-policy.md) 中 owner 确认的矩阵。CLI 有界面但沿用现有 Ink
文本交互；MiniSpec 的用户是本地单用户，目标是在未来 Tools 请求授权时给出明确、不可复用的选择。
当前尚无文件/命令执行器。本 PR 接入模式参数和本地命令，审批请求由可信本地控制器调用；
聊天响应、模型文本、HTTP 返回值都不会被解释成文件操作或人工确认。

## 选择与边界

备选是把授权放在服务端配置，或在每个 Tool 中独立询问。本轮选择 CLI 本地控制器复用同一策略，
因为项目根、文件系统和键盘确认都在本机；不增加服务端配置源、HTTP 审批接口或通用执行器。
审计写入/查询仍属于 3/3，**Refs #34，不关闭 Issue**。

模式仅控制未来的文件/命令 Tools，不控制已有聊天、记忆软删除、Provider 配置或模型费用。
`read-only` 不表示 CLI 不联网，也不表示现有 API 都只读。

## 用法

```sh
mnemic chat --project PROJECT_UUID --approval-mode confirm --root /absolute/project
mnemic resume CONVERSATION_UUID --project PROJECT_UUID --approval-mode read-only --root /absolute/project
```

省略模式为 `read-only`，省略根目录为启动时当前目录；相对 `--root` 会转成绝对路径并解析真实目录。
根目录须存在且不能是文件系统根。模式和根目录不从服务端或模型加载，模式不会永久保存。
参数只适用于 chat/resume；非法模式、控制字符路径在网络调用前拒绝。

```text
/permissions                    显示模式和真实根目录
/permissions confirm            切换模式（read-only / confirm / auto）
/permissions list               当前项目和真实根内的会话/永久授权及 ID
/permissions revoke UUID        按列表中的 ID 撤销，不能删除其他项目的规则
```

`/permissions` 会显示完整授权目录，不读取其中的记录；即使有坏记录也能查看位置。
list/revoke 因权限或记录损坏失败时，同样给出完整目录并提示手动检查，不回显坏记录内容，
也不会自动跳过或删除记录。修复前审批继续拒绝。

auto 仅免新建确认，覆盖/删除/shell 仍逐次询问；只读拒绝写操作。
最终路径分量为符号链接的删除仍不支持，返回 invalid_target。

## 确认流程

受信本地调用 `ApprovalController.request(operation)` 后，策略返回 ask 才出现提示，展示实际操作、
完整 canonical 目标，shell 还展示 JSON 转义后的原始命令（换行和控制符不会成为终端指令）。

```text
审批确认 · file.create
/absolute/project/src/new.ts
1 单次 · 2 本会话 · 3 永久 · n / ESC / Ctrl+C 拒绝；Enter 不确认
```

覆盖、删除或 shell 只显示单次选择；输入 2/3 无效。普通文字、粘贴内容、Enter 不确认，
也不进入聊天。按 ESC/Ctrl+C 拒绝当前审批而非提交退出；待审批结束后可继续聊天。
复核/保存期间忽略重复按键，每个唯一提示 ID 只能消费一次。旧 ID 不能确认新请求。
确认仅接受无修饰的普通数字按下事件；Meta/Ctrl/Shift/Super/Hyper 数字快捷键及 release/repeat 不确认。
同一控制器只接受一个进行中的请求，其他请求明确拒绝 busy，不替换当前提示。

人工选择后再次评估：目标已从新建变成覆盖，或 canonical 路径改变，就取消该次授权，不能
把对新建的确认用于覆盖。永久规则落盘后也复核，若目标已改变则撤销刚保存的规则。
模式切换、会话 ID 切换和关闭取消等待中的审批。单次选择不存入任何可复用规则。
会话身份由 ChatSession 同步通知，包括新建失败前丢失旧 ID，以及后续发送重新创建 ID 的路径，
因此旧会话授权在新会话 HTTP 消息发出前就已清空。
这仍是元数据快照；后续执行器必须遵守 1/3 的系统调用处重新核验要求，不能把结果当执行凭证。

## 授权生命周期与存储

- 本会话规则仅存内存，精确匹配 canonical 路径；`/new`、`/resume` 得到另一会话 ID 时清空，退出丢弃。
- 永久规则按项目 UUID、真实根、file.create 和真实目标路径精确匹配，重启后读取；不做目录递归授权。
- 默认存储为用户家目录下 `~/.mnemic-approvals/`，不是项目内可被拉取的配置文件。
  目录要求当前用户所有且无组/其他用户权限（新建 0700），文件同样要求私有（新建 0600）。
  只保存 UUID、路径、操作和授权粒度，不保存 Token、文件正文或 shell 命令。
- 每条规则一个随机 UUID.json，独占写临时文件并发布完整记录，不用覆盖整个数组，因此并发新增
  不会互相抹掉；同一精确规则可能有多个 ID，撤销时按 ID 操作，全部撤销才消除全部匹配规则。
- 读取不会创建目录；每次请求重新读取永久规则，所以其他 CLI 实例撤销后，下一次评估可见。
  撤销不追溯取消已经返回的评估结果，结果也不是可重放执行凭证。
- 拒绝链接/非普通文件/多硬链接的授权文件、损坏内容、可复用危险操作、过宽权限和过大记录。
  最多加载 1000 条、每条 32 KiB；异常时不给权限，并提示检查本地授权存储，不静默修复或忽略坏记录。
  若发布后的复核异常，会尝试撤销刚发布的规则；持续 I/O 故障可能使清理也失败，此时需人工检查
  本地目录后再继续，不能把 storage_error 当作“磁盘上肯定没有授权”。

存储基于 Node POSIX 文件语义，验证平台为 macOS 和 Linux；没有声称 Windows 行为已验收。
授权文件是可信本地用户管理的策略数据，不能抵御同 UID 进程或管理员篡改，不构成 OS sandbox。
项目根内的硬链接别名和检查/使用间竞态仍需未来执行器处理。

## 验证契约

测试使用独立临时目录，覆盖真实落盘/重开/撤销、并发新增、坏记录/链接/权限拒绝，
单次重问、会话切换、永久授权跨实例撤销、危险操作一次性、过期提示、并发和目标变化。
Ink 测试通过真实输入事件验证模式切换、待审批屏蔽聊天、Enter 不确认、ESC/Ctrl+C 拒绝。
测试不向模型请求工具，不执行所展示的命令，也不读写真实授权目录。

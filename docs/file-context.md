# 本地文件引用基座（#35，拆分 1/3）

本轮是无交互界面的 MiniSpec 与本地组件，供后续 CLI 接线使用；实现方案随 PR 交给 owner 审阅。
需求来源为 Issue #35、Proposal #1 的来源权威决策，以及 #34 的项目根边界。
**Refs #35，不关闭 Issue；当前聊天输入、HTTP API、消息与 Evidence 写入均未改变。**

## 范围与取舍

本地用户希望引用 `@README.md`、`@"src/a b.ts"` 或 `@src/`，而不是手动复制大段文件。
本轮先确定解析、有限读取、目录清单、路径补全和带边界的数据格式。
备选是一次接入所有层，或把文件直接拼成用户消息。选择先交付本地组件，避免文件在后续链路中
被当成用户明确陈述；文件来源固定为 `PROJECT_FILE`，不从内容推断为 `USER_EXPLICIT` 或工具输出。

使用已有 Node 文件 API 和 `ApprovalPathSchema`，不引入扫描器、shell、glob、第二份项目根配置。
`evaluateApproval` 只是元数据快照，不当作文件读取凭证；读取处自行检查真实文件身份。
读取属于 #34 三种模式均允许的操作，本轮不添加写权限，也不创建授权规则或审批审计。

后续拆分计划：

1. **本轮**：本地组件与真实临时文件系统测试；现有 CLI 尚不会消费这些组件。
2. **2/3**：消息附件契约与 Evidence 来源传递，服务端按通道强制 `PROJECT_FILE`，经过既有脱敏与写入链路。
   命令/工具输出通道将固定为 `TOOL_OBSERVATION`，不能靠文件正文声称自己是工具输出。
3. **3/3**：CLI/Ink 在发送前显式加载与展示截断提示、Tab 路径补全，串接真实 HTTP/PG 的来源验收。

当前只完成来源标签的本地构造，不代表 #35 的“随 Evidence 传递”或“实际注入回答 prompt”已经验收。
自动选取语义关键文件、递归全库索引、文件编辑、命令执行、文件监听均不在本轮范围。

## 接口与语法

位置：`apps/cli/src/file-references.ts`、`apps/cli/src/file-context.ts`。

```ts
parseFileReferences(text: string): { path: string; start: number; end: number }[]
loadFileContext(root: string, text: string): Promise<FileContext>
completeReferencePath(root: string, prefix: string): Promise<string[]>
renderFileContext(context: FileContext): string
```

`root` 由可信本地调用方从项目根传入，须为已有绝对目录，拒绝文件系统根；允许根本身的符号链接别名。
结果只含相对项目路径，既不携带真实根绝对路径，也不包装原始文件系统异常。
没有引用时直接返回空上下文，不探测根目录。

- 在消息起始或空白之后识别 `@path`；路径含空格时写 `@"path with spaces"`。
  引号内容按字面读取，不支持引号转义。裸路径遇空白结束，标点算文件名的一部分；
  引号结束可跟空白或常见句末标点，否则报 `invalid_reference`。
- 邮箱 `a@example.com`、嵌入文字的 `name@file`、单个 `@` 和 `@@file` 不算引用。
  这不是 Markdown 解析器，代码块中的空白起始 `@path` 仍符合本语法。
- 路径只接受项目内相对路径；允许 `./src/../README.md` 和 `@.`。
  拒绝规范化后越界、绝对路径、Windows 盘符、反斜杠、`~`、控制字符与双向控制字符。
  不展开 `$VAR`、`$(...)`、`*` 或用户主目录。
- 原文 `start/end` 是 `String.slice` 使用的 UTF-16 偏移，不是 Ink 光标的 Unicode 码点偏移。
  消息上限 8000 字符、最多 8 个显式引用；重复引用仍计入输入数量限制，读取时再按规范化路径去重。

补全函数接收不含 `@`/外层引号的路径前缀，只枚举目录元数据，返回相对路径；目录尾部有 `/`。
如 `src/` 返回 `src/index.ts`，空前缀返回根目录候选。
二进制文件也可能出现在候选中，读取时仍须检查；当前组件不负责 UI 加引号或处理键盘。
非法、缺失、受限或超限目录返回空候选，不回退为项目外搜索。

## 读取与资源边界

以下数字是本实现可调的资源策略，非 Issue 给出的性能指标或模型 Token 预算；统一定义在 `FILE_CONTEXT_LIMITS`。

| 限制         | 本轮行为                                                                              |
| ------------ | ------------------------------------------------------------------------------------- |
| 单文件       | 最多 16 KiB UTF-8 内容，额外读取 1 字节判断是否截断                                   |
| 总正文       | 最多 64 KiB UTF-8，不按字符数或 Token 估计                                            |
| 正文文件数   | 最多 8 个，显式文件优先于目录自动选择                                                 |
| 目录         | 单层最多枚举 200 个实际条目，包含被过滤的条目；超限拒绝整个目录，不静默选择不稳定子集 |
| 目录关键文件 | 每个目录最多选取 4 个已有普通文件，不递归遍历                                         |

目录清单按字典顺序返回直接子文件/子目录名称。正文按固定顺序尝试：
`README.md`、`README`、`package.json`、`tsconfig.json`、`pyproject.toml`、`Cargo.toml`、`go.mod`、
`src/index.ts`、`src/main.ts`、`index.ts`、`main.py`。只有这几个已知入口会额外探测，子目录不做通用递归。
同一文件被显式引用并被目录选中时只读一次。

普通文本严格按 UTF-8 解码，拒绝 NUL、非法 UTF-8 和除 Tab/CR/LF 外的 ASCII 控制字节。
截断不会切出半个 UTF-8 字符，也不加入替代字符冒充原文；文件带 `truncated: true` 并有对应 warning。
不承诺识别所有二进制格式：只含合法 UTF-8 可打印字节的文件会当作文本。

任一显式文件加载失败或超过总预算，整个加载调用失败，不能把部分内容当作完整结果发送。
目录自动选择的文件若二进制、不可读或超预算，则跳过并在 warnings 中明确记录原因；
不存在的惯例文件名不制造 missing 警告。
未来调用方须展示 warnings，再决定是否发送，不能把静默缺失当作用户知情。

## 文件系统与数据边界

- 项目真实根以下所有符号链接均拒绝，包括内链、外链、坏链接和链接环；目录清单和补全不展示链接。
- `.git`、`.ssh`、`.aws`、`.gnupg`、`node_modules`、`dist`、`coverage` 路径分量会过滤；
  `.env`/`.env.*`（包含 `.env.example`）与 `.pem/.key/.p12/.pfx` 文件拒绝显式读取。
  比较不区分大小写。这是常见敏感/生成路径保护，不是完整密钥识别、PII 检测或 gitignore 实现。
- 只读普通文件；FIFO/设备等特殊文件拒绝。使用有限 FileHandle 读取，no-follow/non-block 标志，
  打开前后对比文件身份、大小和修改信息，并重查路径组件，检测到变化则拒绝。
  文件系统调用失败只返回稳定 `FileReferenceError.code`，不回显绝对路径、原始异常或内容。
- 这是面向本地可信工作区的保护，**不是 OS sandbox**：Node 没有在这里建立 openat 目录描述符链，
  不声称能防住恶意进程反复替换祖先目录、特意构造的硬链接或所有并发写入。
  不适合用作服务端任意路径读取器。
- 没有网络、缓存、持久化、文件修改、工具执行或模型调用。未扫描用户真实项目或 `.env`。
  后续发送前仍需来源隔离、Secret 脱敏和用户可见的提示；本轮不宣称内容可直接安全上传。

## Prompt 数据格式与验收

`renderFileContext` 把相对路径、固定来源、正文、截断和目录/warnings 一起 JSON 序列化，
放在 `<mnemic-file-context>` 与 `</mnemic-file-context>` 两行之间。
payload 中 `<`/`>` 与双向控制字符转成 JSON Unicode 转义，因此文件中的伪造结束标签不能关闭数据块；
JSON 解码仍可还原原始文本。无引用则不产生块。
边界编码不等于模型能抵抗 Prompt Injection：未来接线必须把文件作为非可信数据并与用户指令分开。

自动化验收使用自己的临时目录：

- 引用语法/UTF-16 偏移、数量限制、越界和字面路径；
- 普通文本/二进制/FIFO、UTF-8 截断与总预算、目录关键文件/清单/去重；
- 根目录别名、链接拒绝、敏感路径过滤、元数据补全、文件系统只读；
- 在真实 open 边界替换最终文件、父目录或文件内容，确认拒绝返回；
- 伪造 Prompt 边界仍只产生一对边界、原文可逆且来源不能自动提升。

真实发送、来源落库和 Ink/PTY 完整交互尚待后续两轮验收；本 PR 不更改 README 用法。

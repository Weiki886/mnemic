# 精排管理开关的实例能力门控

#22/#9 的部分交付。库调用方同时提供经过校验、复制冻结的 recallBinding 与 chatRetrievalBinding，
且满足它们既有的 DB、主密钥和持久日配额条件时，当前 buildApp 实例才允许 PUT /v1/config/flags
将 reranker 设为 true。能力由注册时的布尔值捕获，HTTP body/query 不能申请或覆盖。
任一绑定缺失时仍400；decay/read_time_resolution 一直400。默认 index.ts 未安装绑定，行为不变。

管理更新沿用鉴权、严格输入、CAS、同事务审计和 no-store。不会读 Provider、解密 Key、探测端点、
预留模型配额或发起模型调用；能力可用不等于 Provider 配置齐备或端点健康。选择/校验仍在实际
检索时完成，缺失/损坏时沿用已有失败语义，不自动切换 Provider。关闭后保留所配融合，停止新增
Score 请求，但不会撤销正在运行操作的已冻结快照，也不证明供应商停止计费。

这是单实例能力判断。配置仍为数据库全局单例，不证明其他共享该库的进程也具备绑定；多实例
部署必须先统一所有实例能力再启用，否则未绑定实例仍会 fail-closed 或无记忆降级。
本轮没有增加分布式能力协商、Provider 可用性承诺、环境变量、默认开启或正式启动器接线，
不关闭 #9/#22，真实质量和完整消融指标仍待验收。

测试使用自建随机 PG 库与本地 Score 服务，覆盖真实 PUT→JSON/SSE/recall→关闭链路和审计；
更新开关时断言模型用量及请求均为0。未调用真实/付费模型或改动用户服务。
回滚前先用当前 revision 将 reranker 关闭；旧版本拒绝启用但仍能读取及修复，无数据库迁移。

# 会话续聊决策（#31）

2026-10-20，经所有者确认：**创建续聊会话，旧会话保持只读**。CLI 功能只做文字规格，不新增 Web 页面。
本文件记录本次决定；后续行为变更另行记录，不改写当时的取舍。

## 用户故事与取舍

昨天 `/exit` 后，今天从 `sessions --project UUID` 找到会话 ID，执行 `resume ID --project UUID`。
新会话必须拥有昨天的消息及当时的记忆引用，同时不把旧事实当成新 Evidence 再提取一遍。

备选方案：重新打开原会话、复制消息到新会话、在新会话中引用历史。
选择引用历史：重新打开破坏“旧会话只读归档”，复制正文会重复 Provenance 和提取输入。
使用现有 `conversations.meta.resume` 保存版本号、来源会话 ID 和扁平化消息 ID 列表，无正文、无新表。
引用缺失、格式错误或指向其他项目时失败，不静默截掉历史。

## 行为

- `mnemic resume ID --project UUID`：显式 ID 恢复，无交互选择器；需 TTY。
- `/resume UUID`：对话内切换。同一事务检查项目内来源/当前会话，按 ID 顺序锁定，归档并创建新会话。
  不存在或跨项目统一 404；失败不提前归档当前会话。专用 `manual-corrections` 会话不能恢复。
- 已归档来源不改动其 `ended_at`。开放来源也可恢复；只归档，不把原会话重新设为开放。
- 新会话引用创建时已持久化的完整历史快照；再次恢复将引用扁平化，不递归遍历或复制正文。
  详情展示继承历史与新增消息，列表消息数包括继承历史；同时间按消息 ID 稳定排序。
- `/new` 仍是无历史的新会话，`/exit`/Ctrl+C 仍等待当前请求后提交。恢复、切换和发送均不自动重试。
- 服务端每轮发送使用完整历史与当前消息，而非只传当前问题。历史工具输出仅作文本，不执行工具。
  历史引用在同项目内按版本现查，作为历史消息内容，不提升成系统指令；当前检索事实优先。
- 已删除/失效信念不会被额外重新注入；原始消息里的历史文字仍保留，不等于硬删除或删除传播（#11）。
- `abstained` 仍描述当前检索是否拒答；`history_included` 描述是否给模型提供了历史。
  CLI 在有历史时提示“未召回跨会话记忆；已提供会话历史”，不强行把一个可续聊的回答标成“不记得”。
  这个标志不证明历史中一定有问题答案；模型仍应在上下文不足时明确不知道。

## 安全、计费和并发边界

UUID 只限定项目数据范围，不代表用户鉴权；沿用 #20 的单用户 Bearer Token。
历史元数据、消息 ID 和记忆版本 ID 都不被直接信任：查询重新断言项目，CLI 验证恢复响应的项目、来源和新 ID。
服务端不接受客户端传入的历史正文或引用列表。

归档开放会话会按既有 commit 规则提取尚未认领的用户消息，**可能调用模型计费**；
已提取的旧消息和继承的 ID 引用不再提取。已归档且写回已完成的会话，恢复本身无需调用聊天模型；
发下一条消息才调用应答模型。测试使用离线替身，显式置空真实模型 key。

另一个客户端在生成期间恢复会话时，迟到回答不再追加到归档会话，原请求返回 409；
此前已保存的用户消息保留并进入恢复快照。模型调用可能已经计费，当前不支持即时取消（#33）。
只有创建时已经持久化的内容属于快照，不等待其他客户端未完成的生成。

没有新增幂等键；响应丢失时新续聊会话可能已创建，请先查列表，不盲目重试。
写回仍是进程内任务，持久重试归 #21。长会话完整传入模型，不自动摘要或静默截断，
可能触及提供商上下文上限；预算/压缩留给后续能力，不承诺任意长度都可应答。

## 验收例子

1. 关闭 CLI 后从服务器列表找到旧 ID，重启并恢复为新 ID；原会话仍结束，新会话能继续发送。
2. 离线应答模型实际收到旧 user/assistant 原文、当时的记忆版本值及当前新问题，角色顺序可验证。
3. 连续恢复两次，旧消息 ID 不重复、旧记录没有被复制，Observation/证据计数不因恢复增加。
4. 跨项目来源或当前会话返回 404，非法 UUID/正文返回结构化 400，坏历史引用返回 409。
5. `/resume` 切换后展示净化的历史及引用；`/new` 清空上下文，退出只提交当前续聊会话。
